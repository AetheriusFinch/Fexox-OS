About the "CFS-scheduler" Task Scheduler for Fexox OS (Inspired by Linux)

How It Works
1. Task Selection for ExecutionAll tasks in the TASK_RUNNABLE state are stored in a min-binary heap (run_queue_t), ordered by their vruntime values. The scheduler always selects the task with the smallest vruntime (i.e., the one that has received the least CPU time relative to its priority).Weights are retrieved from the prio_to_weight table. A higher-priority task has a greater weight; as a result, its vruntime grows slower, allowing it to receive more CPU time.To prevent new tasks from gaining an unfair advantage over old ones (and vice versa), g_sched.min_vruntime stores the lower bound of vruntime. New and awakening tasks receive a vruntime no less than this value.

2. Time Quantum and Tick HandlingEvery timer tick triggers sched_tick(), which accepts a pointer to the register frame of the interrupted task (frame_rsp).Preemption conditions (need_switch):The task has exhausted its time slice (SCHED_TIMESLICE_NS, set to 4 ms).A task appears in the queue with a vruntime that lags behind the current task's vruntime by more than the time slice (4 ms).The current task is idle, while there are other ready tasks in the queue.

3. Context Switching (context_switch)Saving State: The current frame_rsp is written into prev->ctx.rsp.Updating vruntime: The weighted time delta, measured via rdtsc(), is added to the current task's vruntime.Address Space Switching (CR3): Each user process has its own page table (pml4_phys). If the next task belongs to a different process, the CR3 register is reloaded.Cleaning Up ZOMBIEs: If the previous task has terminated (TASK_ZOMBIE), its kernel stack (kstack_base), page table (pml4_phys), and the task control block (task_t) itself are freed directly during the context switch.Updating TSS and MSR: To ensure correct return and handling of interrupts/system calls in Ring 3, tss_set_rsp0() and syscall_set_kstack() update the kernel stack pointer top for the current thread.Restoring State: The function returns next->ctx.rsp. The assembly handler switches RSP to the new task's stack and transfers control to the next thread via pop instructions and iretq.

4. Thread Creation and Initializationsetup_kstack: Allocates a 16 KB stack. At the very top of the stack, it constructs an initial sched_frame_t structure, simulating the CPU state after an interrupt: RIP points to the task_wrapper function, RFLAGS has the interrupt flag enabled (IF, 0x202), and parameters are passed via RDI and RSI according to the System V ABI.task_wrapper: A safe wrapper that executes the target task function and guarantees a call to sched_exit() upon its completion.

5. Synchronization and Lockingspinlock_acquire saves the previous EFLAGS register and disables interrupts (cli), protecting queues and the global g_sched state from race conditions with the timer interrupt.
